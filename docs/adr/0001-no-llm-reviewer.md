# 拒绝由模型自动审查放行

判定只能来自两类主体：人写下的规则，和人当场给出的答复。系统内不存在任何"模型判断这条命令安全，于是自动放行"的路径。

## Considered Options

- **LLM 审查员。** DSH 自带 `@deepseek-ai/dsh-experimental-auto-review`，用大模型对每次工具调用做风险分级并放行低风险项；本项目上一版的 profile 配置里也写着 `mode: rules-and-llm` 和一个 reviewer 模型。因此这不是假想选项，而是"顺手加回来"的成本几乎为零的选项。
- **规则 + 人工。** 只有显式写下的规则和当场的人为答复能产生放行。

## Consequences

摩擦更高。这一点靠三档放行有效期、规则试算器和一套保守的默认规则集来抵消，而不靠让模型替人做决定。

换来的是系统里不存在单点绕过的开关。在"agent 可能被 prompt injection 劫持"这个威胁模型下，喂给审查员的输入恰恰是对抗构造的输入——自动放行路径会把整条护栏降级成一个可以由外部文本控制的门。
