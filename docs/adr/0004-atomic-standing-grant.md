# 长期放行时，生成规则与该规则的确认是同一次人工动作

当人对待审批命令选择「长期并锁定规则」时，系统一次性完成三件事：生成覆盖各待审批命令段的放行规则、写入规则库、并把规则库标记为已确认。这个动作本身就是 ADR-0003 要求的"人工确认"——人明确表达了长期放行意图，不应再让他去规则页点第二次确认。

## Considered Options

- 生成规则后仍留待确认，要求用户再去规则页点一次确认（旧行为）。用户抱怨："看不到生成的规则""再点一次太冗余"。
- 只生成规则不确认，靠后续审批流程兜底。会造成"看起来长期放行了、命令却仍被拦截"的半成品状态。
- **生成 + 确认在一次人工动作内完成。** 采用此项。

## Consequences

- 生成规则的确认态不再由"再次点击"驱动，而由人点击长期放行这一动作驱动；确认的含义没有削弱，只是把两次点击合并为一次。
- 该动作必须是事务式的：生成、保存、确认、放行任一失败都不执行命令，并回滚到未放行状态，在审批卡片里显示失败原因与重试入口。
- 生成规则仍受硬约束：不能覆盖受保护程序、受保护路径、不可判定构造；这些一律不进入普通审批流程。
- 生成结果必须当场可见：审批卡片显示生成了哪几条规则，并可一键跳到规则页高亮定位。
