# 自建审批通道，不复用 DSH 原生 approval

判定为"待审批"时，我们用自己的对话框和队列收集人的答复，而不是把请求交给 DSH 原生的 `ctx.approval`。

## Reasons

原生通道的返回值只有 `allowed-once` / `rejected` / `cancelled` / `unavailable` 四种，而我们需要表达三档放行有效期（仅此次 / 本会话 / 长期写入规则），并且需要在对话框里展示"这条命令被切成了哪几段、哪一段没命中、哪一条规则将要被记住"。原生通道给不了这两件事。

原生通道继续存在，继续管它原本管的事（沙箱升级、其它插件发起的审批），两者叠加而不是互相取代。

## Considered Options

- **复用原生 `{kind: 'ask'}`。** 代码量小一个数量级，一周能做完。代价是只能一次性放行，且对话框里只有一句理由文本——摩擦降不下来，而摩擦降不下来的结局是用户把插件关掉，保护归零。

## Consequences

必须自己实现待审批队列、并发、调用中止语义和整套 UI。随之而来的风险是：审批 UI 一旦坏掉，就没有人能放行任何东西。因此"UI 或通道不可用 → 判定为拦截"必须是硬兜底，不能有"联系不上人就算了吧"的退化路径。
